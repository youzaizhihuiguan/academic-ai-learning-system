# Intelligent UI Composition Guide

本参考用于决定**怎样把已经确定的学习内容呈现得更清楚、更可操作**。它不是教学法、题库规范或课程设计框架，也不是必须逐项实现的组件清单。

## 基本原则

Intelligent UI 的格式服从问题。先问：

1. 当前内容如果只用文字，会缺失什么？
2. 用户需要看、比较、改变、输入、筛选、推进还是直接执行什么？
3. 哪种最小界面能让这些动作自然发生？
4. 如果不用 UI，回答是否反而更清楚？

若答案指向纯文本，就不用 UI。

## 常见表达模式（仅作启发）

| 当前任务 | 可能合适的 Intelligent UI 表达 |
| --- | --- |
| 比较概念、方法、情境 | 并排布局、差异高亮、可切换视图 |
| 看结构或空间关系 | 标注图、关系图、几何/结构示意 |
| 看变量变化 | 图表、参数控件、联动数值与解释 |
| 理解过程或状态 | 分步状态、前进/后退、历史轨迹、调用栈/流程视图 |
| 输入并得到即时结果 | 表单、数字/文本输入、确定性反馈、计算小工具 |
| 查看数据 | 表格、图表、筛选、排序、局部详情 |
| Tutor 已决定要练习 | 输入区、选项、分步提交、反馈区、提示入口 |
| Tutor 正在讲定义/证明 | 条件分区、例/非例对照、步骤展开、局部高亮 |

这些只是呈现模式，不决定**应该讲什么、出什么题、给什么提示或什么答案正确**。

## 组合原则

- 可以把文字、公式、图形、表格、输入和状态自由组合；不要固定“一题一滑块”。
- 同一输入驱动多个视图时，所有派生表示必须一致。
- 复杂界面不等于更好；能用一个图解决的问题不要堆多面板。
- 需要真实运行、外部数据、随机模拟或工具执行时，必须明确来源；UI 本身不能伪造这些能力。
- 用户明确要纯文本、完整答案或停止交互时立即照办。

## 运行环境

只使用当前 Chat 实际支持的 Intelligent UI 能力。不要凭空假设拖拽、动画、3D、异步后台任务、联网、跨聊天状态或自动持久化一定可用。若某种交互不可实现，选用真正可操作的替代形式或降级为静态内容。
