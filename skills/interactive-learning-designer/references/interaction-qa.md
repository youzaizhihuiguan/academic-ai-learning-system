# Intelligent UI QA

只在生成或审查有实质交互的回答时使用。

## 功能与状态

1. **格式是否有价值**：UI 是否比纯文本更清楚、更可操作；若没有，退回简单回答。
2. **状态是否一致**：输入改变后，公式、数值、图形、表格和文字说明是否同步。
3. **控件是否真的工作**：按钮、选择、输入、下一步、返回、重置等不能只有外观。
4. **边界输入**：缺失、不合法、极端值、无解、多解、空状态是否有合理处理。
5. **可逆与可读**：复杂状态能否回退/重置；标签、焦点、公式和布局是否易读。
6. **运行时诚实**：不假设当前 Chat 支持未实际可用的拖拽、动画、联网、后台执行或持久化。

## 内容一致性

1. UI 不能改写领域 Tutor 已确定的定义、条件、答案标准或模型假设。
2. 图形直觉不能冒充数学证明。
3. 随机模拟不能冒充理论必然或真实观测数据。
4. 教学动画不能冒充程序在用户环境中实际运行。
5. 练习反馈只能使用真实判据；开放证明、统计结论、复杂代码行为需要领域推理或工具核验。

## 证据边界

客户端本地状态若没有通过支持的事件、用户提交或可信产物回传，不得宣称模型已经观察到。UI 操作本身也不自动等于学习 Evidence 或长期掌握。
