# Interaction QA — Capability, Semantics, State

## 确定性检查

1. **概念与数学**：用户改变参数时计算结果与文字解释是否一致？极值、符号、维度、零分母、无解/多解、数据有限性是否正确处理？数值探索不能替代证明。
2. **模拟与真实数据**：说明模拟分布、已知真值、采样次数、随机性与不确定性；没有运行过的模拟不冒充实测结果；回测也不能冒充样本外检验。
3. **程序执行**：状态动画是一个说明模型还是实际调用代码的结果？复杂操作可能有网络、异步、错误处理等隐藏状态，不能用简化流程图否认这些条件。
4. **输入控件**：最小/最大/缺失/不合法输入是否处理；控件初值与显示值是否一致；“下一步/提交/重置”是否真能执行对应动作。
5. **反馈**：确定性题目可显示即时对错，但开放题、证明与统计结论必须有进一步评估；不能硬编码看似智能的评分来装作推理。
6. **持续性**：用户在原界面内的状态是否只局限本轮？中断、重新打开、跨会话时不要保证继续。交互动作如果未被支持的回调/用户消息送回模型，不得宣称已经捕获。
7. **表达质量**：阅读负担、标签、对比度、公式可读性、移动端布局、多操作时的焦点与反馈是否恰当。
8. **降级**：组件不可用、运行模式不支持或用户想直接答案时，用普通文字/公式/静态图/代码回退，核心解释必须依然正确。

## 代表性反例

- 数学："一条滑块"显示矩阵行列式归零，只能说明当前变换退化，不能据此证明一切有限维情形。
- 统计：把随机抽样图的一次运行结果写成理论必然值，属于错误。即使图形漂亮也判失败。
- 编程：递归调用栈 UI 未真的执行程序，不能声称用户项目已经测试通过。
- 学习证据：用户点对两道选择题不代表已经独立证明了整个单元；没有回传的点击，更不能自动写入长期记录。

若任何交互缺少可验证的学科基础，就明确表明示意/假设/尚未核实的部分，并提供可用的审查路径，不靠更复杂 UI 掩盖问题。
