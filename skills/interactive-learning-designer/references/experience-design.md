# Native Intelligent UI — Open-Ended Learning Experience Design

本文件仅在需要拓宽创作思路、设计有实质交互的学习体验、或优化已有 UI 时阅读。**不是功能清单、组件库规范、固定模板或每次回答的输出格式。** 从学习内容和学生可做的认知动作出发，利用当前 Chat 能力自由组合新的形式。

## 1. 学习问题决定界面，而不是反过来

先完成一个内部设计句子：

> 我想让学生通过【可操作的变化/构造/选择】观察【原本不易看清的关系】，进而理解【定义、规律、过程、边界或反例】。

思考四个互相关联而非顺序必选的维度：

- **对象**：学生正在理解的是量、方程、关系、集合、图结构、概率分布、流程、系统状态、论证条件还是实际数据？能否让其中重要部分被选中、分解、修改或重新组合？
- **作用**：什么是他可以控制的？条件、输入、初值、观察角度、操作顺序、假设、约束、样本来源、策略或表述层级？控制后什么可被观察到？
- **联系**：同一知识是否有符号、图像、表格、几何、时间和解释等多个表示？其中哪两个应联动、并排比较或按需切换，才能让学生发现结构？
- **发现**：学生最终应观察不变量、违例、误差、机制、边界、反事实，还是完成一次独立预测和验证？什么反馈能准确解释 *why*，而非仅显示绿色对勾？

这些是生成新体验的**设计坐标**，不是只能选的四种 UI。

## 2. 可自由组合的体验语法

下面是可能的认知动作与表达方式；任何一类都可增删、变形、嵌套或不用。**不要将“默认控件”“标准课程小游戏”“一题一个滑块”固化为模板。**

| 认知动作 | 可能的实现线索（均非强制） | 学习价值 |
| --- | --- | --- |
| 改变、干预、探索 | 参数与图像/结果/解释的联动、条件切换、极限与敏感性视图 | 看到依赖、单调性、退化、临界点和反直觉结果 |
| 构造、拆解、组合 | 选点连线、结构编辑、向量/集合/图节点构造、按层揭示 | 把定义转成满足或违反条件的可操作对象 |
| 时间、步骤、状态 | 手动推进、退回、跳步、分支路径、状态对照与历史标记 | 跟踪“为什么下一步是这样”，定位首次分歧 |
| 对照、关联、切换视角 | 图—公式—表—文本联动、相邻场景、等价表示、一致性高亮 | 看清同一对象的不同表示及差异来源 |
| 预测、检验、反驳 | 先预测后揭示、生成最小反例、带解释的即时反馈、尝试其他策略 | 用自主尝试发现条件和局限，训练迁移而非识别 |
| 定义、出题、检索与迁移 | 定义拆解/重建、例与非例、开放题、变式、提示、答案解释、跨表示迁移 | 把“看懂”转成可观察的回忆、辨析、执行与迁移 |
| 探究证据、模型与不确定性 | 模型假设选择、理论对照模拟、数据与置信区间比较 | 分清在什么前提下能支持何种结论 |
| 解释复杂关系与决策 | 多变量情境、分层结构、约束调整、反事实比较、交互式解释 | 比较机制、代价与后果，而非背诵一个值 |

表达媒介可以自然混合 Markdown、数学公式、信息布局、结构/几何/状态图、图表、可点击的注释、按钮、选择、输入、反馈面板及对话追问。在适合的平台或明确的可执行工具支持下，还可采用更专门的可视化形式。**调用前先检查当前真正支持的交互与事件，不许虚构拖拽、3D、动画、联网或自动保存。**

## 3. 跨学科启发——不是八个预制小工具

- **数学分析**：控制 ε 和 δ 的邻域，观察量词先后及为什么某个 δ 不够；或让学生构造逼近却不收敛的反例，再把直觉接回定义。
- **高等代数**：切换基底、线性映射与坐标表示，观察哪个对象变、哪些代数性质不变；也可以由学生自己构造矩阵并寻找不可逆边界。
- **常微分方程**：选择初值、比较方向场与解曲线，观察平衡点和稳定性；直觉必须受方程、存在唯一性等真实条件约束。
- **概率与统计**：让样本量、生成机制或估计方法发生变化，并列展示理论对象与具体模拟；可邀请学生预测覆盖率或偏差，再核对前提，不把抽样图当定理。
- **经济学与金融**：分别改变供需条件、弹性和约束，观察均衡、剩余与福利；比较一个冲击与另一个冲击，区分模型推论和实测数据。
- **算法与系统**：学生选择下一步调度、递归展开/回溯、搜索边扩展或缓存策略，多个面板共同展示执行栈、队列、变量和时间/空间代价。
- **逻辑与证明**：通过修改量词、假设和反例对象观察命题何时变假；探索能启发证明，但不能替代完整、一般性的论证。
- **AI/ML**：展示张量形状、梯度传递或模型决策的不同层；明确哪些是教学简化模型、哪些来自实际执行或可核验实验。

任何学科都可以提出未列举的交互语法，例如分层解释、分类辨析、可操作时间轴、多情境联动或把用户给出的真实数据转成可探索的结构。**不要因本页没有示例就拒绝发挥 Intelligent UI。**

## 4. 交互体验的深度不是控件数量

- **局部**：一次观察能回答关键问题时，一个图或简短控件即可。
- **连贯**：多步变化重要时，让状态可前进、返回、重置并显示当前步骤为什么成立。
- **对照**：误解来自相似概念混淆时，优先做联动对比，突出差异与成立条件。
- **探索**：可以提出假设、调整条件、观察结果、发现异常再追问。允许与现实模型或自我预测发生分歧，并解释为何。
- **练习**：需要学生作出判断时，给出可解释的反馈、适量提示和可选重试；不要把练习变成强制认证。

目标是**更少认知负担、更高解释能力**。学生控制权、可阅读性和教学相关性均比 UI 华丽程度重要。

## 5. 运行时与证据纪律

在 Chat 内优先采用真实可用的原生组件和可观察状态，保证控件确实改变对应数据与视图；不要将 HTML/JS 代码示意冒充平台已运行的 UI。若用户明确请求独立应用、复杂自定义可视化或特定工具，可用受支持的其他工具，但这种请求不是普通学习 UI 的前提。

区分四种结果：由公式算出的值、设定模型下的模拟、来自真实工具的运行结果、从可靠外部来源获取的数据。它们可互相核查，但不能互相伪装。客户端局部交互不能默认为模型已观察或跨聊天存储；要经真实提交、支持的事件或可信产物才能进入后续 Evidence。

**最后自检**：去掉界面后，学习者失去的是哪种观察或操作？如果没有失去重要东西，退回更简单的回答。若学生愿意继续操作，下一步是否自然开启新的有根据的探索，而不是一套固定题库？
