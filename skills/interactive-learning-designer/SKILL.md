# Intelligent UI 学习增强层

把 **Intelligent UI 当作回答媒介，而不是新的教学体系**。目标是让领域 Tutor 在适合的时候充分使用 ChatGPT 可组合的文本、视觉与交互能力；不要把本 Skill 变成第二个数学/统计/计算机导师，也不要发明一套独立的“交互学习法”。

## 职责边界

- **领域 Tutor 管内容。** 定义怎么讲、出什么题、证明是否成立、统计结论是否可靠、代码状态是否真实、何时直接给答案，均由相应 Tutor 或可靠来源决定。
- **本 Skill 管呈现与交互。** 判断这些内容是否值得用 Intelligent UI 表达，并选择最合适的布局、图示、图表、控件、输入、对照、步骤、状态或小工具。
- 定义、例题、练习、反例、提示等都**可以被 UI 呈现和操作**，但它们不是本 Skill 独有的教学能力；本 Skill 不因为能显示一道题就接管出题逻辑。
- 普通文字已经最清楚时，直接保留文字。不要为了“触发 Skill”强行增加组件。
- 本 Skill 可以单独被选中，但不能假设能够自动调用另一个 Skill；遇到学科正确性不确定的内容时先核实或明确边界。

## 使用流程

1. **读取 Learning Intent 与领域内容。** 明确用户现在要理解、比较、操作或完成什么，以及 Tutor/上下文已经给出的定义、公式、题目、数据、步骤或结论。
2. **判断 UI 是否真的有增益。** 只有当视觉组织、直接操作、状态变化、并排比较、输入反馈或即时工具能明显改善理解或操作效率时才用。
3. **让格式服从问题。** 根据当前任务自由组合可用的原生文本、公式、布局、图形、图表、按钮、选择、输入、表单和交互状态；不固定成滑块、测验或任何模板。按需参考 `references/intelligent-ui-composition.md`。
4. **让交互真实工作。** 控件必须改变对应状态或视图；派生数值保持同步；错误输入、边界值、切换和重置必须有实际行为。复杂状态按需执行 `references/interaction-qa.md`。
5. **保持内容与界面分层。** UI 可以帮助展示定义、练习、证明步骤、模拟或代码状态，但不能把视觉现象冒充证明、把示意动画冒充真实程序执行、把模拟冒充实测数据。
6. **只报告真实可见状态。** 客户端本地点击不一定进入模型上下文。只有用户提交、支持的回调或可信工具结果才能形成可核查的 Interactive Observation；需要交接时参见 `references/interaction-contract.md`。

## 与系统其他 Skill 的关系

- `rigorous-math-tutor`、`statistics-quant-lab`、`computer-ai-tutor` 等决定学科内容与判据；本 Skill 只增强这些回答的 Intelligent UI 表达。
- `course-tutor-builder` 决定课程级 CLP；本 Skill 不改变课程路线。
- UI 操作本身不是 Evidence。若领域 Tutor 已形成可核验 Evidence，且用户确有持久化诉求，再由 `learning-progress-coordinator` 按其规则处理。
- 只有用户明确要求 Obsidian 时才进入知识库流程。

## 降级

当前模式不支持所需 Intelligent UI、用户明确要纯文本，或交互没有明显收益时，退回普通文字、公式、静态图、表格或可复现实验说明。核心学科回答仍应完整可用。
