# Progress / Evidence Contract

本参考在恢复、改变或交接持久学习进度时使用。保持原仓库的 source-of-truth：稳定规则在 Profile，变化的事实在 Progress；重要程序/实验产物保留在各项目仓库，Progress 只链接证据与能支持的结论。

## 四种概念不同，不新增平行数据库

- **Progress**：课程位置（若已知）、本轮目标、已确认里程碑和下一步。未知绝不等于未完成。
- **Evidence**：观察到的学习者行为或产物，以及验证范围；尽量复用源链接（练习答案、证明、测试输出、教师反馈）。
- **Learning Debt**：为了当前主线刻意推迟的**必要**前置及回收触发点；普通错误或复习安排不自动成为 Debt。
- **Review Queue**：需要未来从记忆再现、区分概念或独立解决变式的知识；不等于长期欠账，也不一定带指定日期。

## 最小 Evidence 结构（按事件裁剪）

- `topic / learning_objective`：对照 CLP 的具体能力；不借别的课的阶段代码。
- `observation`：用户自己说/写/做了什么或可验证的作品表现。
- `assistance`：`demonstration_only | hinted | unaided | delayed_unaided | transfer_unaided | unknown`；辅助程度是观察属性而非统一全科分数。
- `verification`：由领域 Tutor/执行工具/可靠来源检查过什么；没有则标为 pending。
- `scope_and_limits`：此次结果支持什么；不支持什么更大结论。
- `source_ref`：确实存在的聊天内容或文件/项目运行报告；不要编造永久 URL。
- `observed_at`：已知才记录；日期不应成为没有证据的准确时间。

状态和分类为概念说明，按当前课程的原有文件格式最小插入；不强制把 markdown 转 JSON 或复制每个作业文件。

## 写入与恢复门槛

1. 明确课程和目标文件，读取其当前状态与先前依据；先有真实 Evidence，再判断是否变更。
2. 确认所有者/仓库可见性/用户授权；公开仓库默认只适合非私人模板、合成测试数据和公共课程材料。个人答题、表现和成绩不自动写公开仓库。
3. 仅修改变化字段/段落，保留其余内容及人工注释；已有相同记录时避免重复追加。出现并发变化时重新读取和合并，不无条件覆盖。
4. 实际写入后回读验证所选目标/内容/链接；若无法验证，说明写入结果未知，不宣称成功。
5. 无写权限、无合适私有目的地或用户不希望存储时，提供可复制的最小草案，清楚标记**未持久化**。
6. 下次恢复优先真实来源，不依据聊天模型的可能记忆修改 Progress；没有记录时先正常回答能独立完成的问题，需要晋级再问关键缺失证据。

## 可变状态迁移边界

现有 `progress/computer.md` 为 markdown 轻量模板，原生阶段 P00–P31 仅属于其计算机学习路线。新增 Review Queue 应为可选小节，只在真实任务出现时建立；保留阶段/项目/债务与历史证据位置，不复制到 Obsidian。
