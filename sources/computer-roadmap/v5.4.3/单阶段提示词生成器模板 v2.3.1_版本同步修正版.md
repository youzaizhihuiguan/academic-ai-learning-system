# 单阶段提示词生成器模板 v2.3.1

## 0. 本模板定位

本模板用于把：

1. 长期总路线文件；
2. 最新学习文件夹记录；
3. 目标阶段代码；
4. 当前补充说明；

转换成一份可用于当前 **Pxx 阶段** 的“单阶段专用提示词”。

单阶段专用提示词不是 1 到 2 周任务表，而是当前 Pxx 阶段的阶段导航。它负责说明：

- 这个阶段为什么现在学；
- 这个阶段学什么、不学什么；
- 本阶段是否包含内嵌支线；
- 本阶段做什么项目、留下什么证据；
- 本阶段完成到什么程度才能进入下一阶段；
- 后续如何用阶段内任务模板继续推进。

一个 Pxx 阶段可以包含多轮任务，也可以根据上下文长度、学习难度和对话是否发散，跨多个对话推进。

---

## 1. 使用方式

使用本模板时，建议提供：

1. 长期总路线文件，优先使用 v5.4.3 或之后版本；
2. 最新学习文件夹记录；
3. 目标阶段，格式优先使用 `Pxx：阶段名称`；
4. 当前补充说明，例如最近学了什么、卡在哪里、接下来时间安排、是否偏数据分析 / 大数据 / AI 应用 / AI 全栈 / 大模型等。

如果没有明确指定目标阶段，AI 应根据长期路线和最新学习记录判断当前最适合进入哪个 Pxx 阶段。

## 2. 输出版本规则

默认生成 **标准轻量版单阶段提示词**，除非明确要求“完整详细版”。

### 2.1 标准轻量版

目标：清楚、可执行、能开始学、能判断是否跑偏。

建议长度：1800 到 3000 字。

标准轻量版只保留 10 个核心栏目：

1. 阶段判断；
2. 阶段定位与边界；
3. 本阶段目标；
4. 必学内容与技术栈；
5. 阶段内嵌支线状态；
6. 项目任务；
7. 推荐资源配置；
8. 文件与输出证据；
9. 完成标准；
10. 下一轮推进与压缩学习记录。

标准轻量版只给**压缩学习记录模板**，不展开完整学习文件夹记录模板。

### 2.2 完整详细版

只有在用户明确要求“完整详细版”时，才在标准轻量版基础上展开附加区内容，包括进入条件、详细知识清单、AI 辅助规则、统计背景转化、专项支线说明、详细文件夹结构、详细资源表、完整防浅检查和完整学习文件夹记录模板。

## 3. 关键规则摘要

以下规则只作为本模板的摘要说明，真正可复制执行的完整提示词见下一节。

### 3.1 长期路线定位

生成单阶段提示词时，必须继承长期路线 v5.4.3 的定位：

```text
当前主线：应用统计背景下的 Python 数据分析、数据科学、机器学习、AI 工程与 AI 全栈转码能力建设
长期参考：FDU 应用统计人工智能方向
专业底色：统计思维、数据理解、指标设计、模型评估、实验设计、大数据与 AI 应用
执行原则：核心能力深挖，工程能力闭环，大模型方向后期聚焦
输出证据：可运行代码、可复现项目、可解释报告、可展示作品、学习记录
```

### 3.2 阶段内嵌支线

支线不再按“外置随机池”的方式处理，也不使用轮次层面的支线数量限制。

```text
阶段层面决定支线归属：
某条支线是否属于当前 Pxx 阶段，是否应该写入本阶段单阶段提示词。

轮次层面决定本轮是否推进支线：
当前 1 到 2 周任务是否需要推进该阶段内嵌支线的一小部分。
```

本模板只判断阶段层面的支线归属、边界和输出物。阶段内任务模板负责判断某一轮是否推进支线。

### 3.3 推荐资源结构

单阶段提示词不能只写“看官方文档”或“找教程”。推荐资源应按结构配置，而不是堆资源清单。

每个 Pxx 阶段的推荐资源优先覆盖：

1. 官方文档；
2. 系统教程 / 课程；
3. 练习 / 项目参考；
4. 速查表 / 工具手册。

标准轻量版推荐 3 到 6 个资源，并说明资源类型、使用方式、本阶段只看哪一部分、是否记录到 `resource_index.md`。

### 3.4 个人复盘说明手册联动

单阶段提示词不仅服务 AI 对话，也要服务用户本人复盘。阶段开始、阶段推进、阶段收尾时，都应保留更新《学习路线个人复盘说明手册.md》的字段。

## 标准轻量版单阶段提示词结构

除非我明确要求“完整详细版”，默认生成标准轻量版。标准轻量版只使用以下 10 个核心栏目。

### 1. 阶段标题

格式：

# Pxx：阶段名称 - 单阶段专用提示词

### 2. 阶段定位与边界

说明：
- 本阶段在长期路线中的位置；
- 本阶段为什么现在学；
- 本阶段和前后阶段的关系；
- 本阶段服务哪些能力线；
- 本阶段不应该提前扩展到哪些内容。

### 3. 本阶段目标

拆成：
- 核心目标；
- 最低完成目标；
- 标准完成目标；
- 可选进阶目标；
- 本阶段应留下的能力证据。

### 4. 必学内容与技术栈

说明：
- 本阶段必学内容；
- 本阶段应会内容；
- 本阶段可选内容；
- 本阶段暂缓内容；
- 使用的语言、库、工具、开发环境；
- 是否需要 GitHub、服务器、数据库、GPU、大模型 API、C++、大数据等。

不要堆太多知识点。每个阶段优先保证能完成、能运行、能解释、能记录。

### 5. 阶段内嵌支线状态

说明：
- 本阶段主线推进内容；
- 本阶段是否包含内嵌支线；
- 如果包含，支线名称是什么；
- 支线为什么属于本阶段；
- 支线服务哪个阶段输出物；
- 支线在本阶段推进到什么深度；
- 哪些内容低频维护；
- 哪些内容冻结观察；
- 后续轮次如何判断是否推进支线。

不要设置轮次层面的支线数量硬上限。阶段层面只判断支线归属和边界；轮次层面才判断本轮是否推进支线。

### 6. 项目任务

最多给出：
- 1 个最小项目；
- 1 个标准项目；
- 1 个可选进阶项目。

每个项目应说明：
- 项目目标；
- 技术栈；
- 输入；
- 输出；
- 简化文件结构；
- README 应包含什么；
- 完成标准；
- 是否适合 GitHub / 部署 / 简历 / 作品集 / 长期参考材料。

不要给跨多个阶段的大综合项目。

### 7. 推荐资源配置

按以下结构推荐 3 到 6 个资源：

- 官方文档；
- 系统教程 / 课程；
- 练习 / 项目参考；
- 速查表 / 工具手册。

每个资源必须说明：
- 资源名称；
- 资源类型；
- 本阶段使用方式：精读 / 跟练 / 查阅 / 练习；
- 本阶段只看哪一部分；
- 是否需要记录到 `resource_index.md`。

不要一次推荐过多资源。如果涉及快速变化技术，提醒优先查官方文档或近期资料。如果明确涉及 FDU 最新招生、复试、方向或导师信息，提醒优先查官方来源。

# 附加区：完整详细版可展开内容

只有用户明确要求“完整详细版”时，才在标准轻量版基础上额外展开以下内容。

## A. 进入本阶段的详细条件

可展开：
- 必须掌握的前置知识；
- 必须完成的前置练习或项目；
- 必须具备的工具环境；
- 如果前置条件不足，应该先补什么；
- 哪些情况下暂时不建议进入本阶段。

## B. 详细知识清单

可按以下层级展开：

- 必学知识；
- 应会知识；
- 可选知识；
- 暂缓知识。

每个知识点可以说明：解决什么问题、学到什么深度、是否需要做练习、是否需要进入项目。

## C. 详细 AI 辅助学习和开发规则

可展开：
- AI 可以帮什么；
- AI 不可以代替什么；
- 如何记录 prompts；
- 如何验证 AI 输出；
- 如何检查代码安全；
- 如何避免泄露 API Key；
- 如何判断是否过度 vibe coding；
- 本阶段是否需要 `prompts/ai_log.md`。

必须强调：

```text
我不能接受自己完全看不懂的 AI 代码。
所有 AI 生成代码必须运行、解释、修改和记录。
```

## D. 统计背景转码优势

如本阶段涉及数据、模型、实验或评估，可展开：
- 如何服务数据理解；
- 如何服务指标设计；
- 如何服务模型评估；
- 如何服务实验设计；
- 如何服务大数据分析、RAG / LLM eval 或科研复现。

如果本阶段主要是工具或工程基础，不要强行写成传统统计课程复习。

## E. C++ / 大数据 / 工程内嵌支线专项说明

如本阶段涉及这些支线，可展开：
- 本阶段是否内嵌 C++；
- 本阶段是否内嵌大数据；
- 本阶段是否内嵌前端、后端、部署或 Docker；
- 如果需要，学什么；
- 如果不需要，为什么不学；
- 是否影响主线。

完整详细版可以根据阶段类型展开目录，例如：

- 数据分析阶段：`data/`、`notebooks/`、`figures/`、`reports/`；

- 论文复现阶段：`paper_cards/`、`baseline/`、`reproduction_log.md`。

完整详细版可以把资源表扩展为：

```text
| 资源名称 | 类型 | 用法 | 本阶段只看哪部分 | 记录位置 |

```

但仍然不要把总路线变成资源堆砌。资源必须服务当前阶段输出物。

## H. 完整防浅学习检查

可展开 8 项防浅检查：

1. 能否不用教程写最小版本；
2. 能否解释它解决什么问题；
3. 能否说清输入和输出；
4. 能否处理常见报错；
5. 能否把它放进项目；
6. 能否写 README 让别人运行；
7. 能否说清它的局限；
8. 能否讲 5 分钟。

如果多数答不上来，不建议进入下一阶段。
