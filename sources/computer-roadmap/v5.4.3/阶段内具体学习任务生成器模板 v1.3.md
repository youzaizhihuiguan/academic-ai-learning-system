# 阶段内具体学习任务生成器模板 v1.3

> 本版由 v1.2 小修而来，只同步四点：统一 Pxx 表达；增加“发现阶段提示词漏支线时怎么办”；推荐资源改为“最多 3 个但类型完整”；增加个人复盘说明手册更新提醒。

## 用途

本模板用于在一个 Pxx 阶段尚未完成时，基于当前 Pxx 单阶段提示词和最新学习记录，生成下一轮具体学习任务安排。

它不负责生成长期路线，也不负责重新生成 Pxx 单阶段提示词；它只在当前 Pxx 阶段内部，安排下一轮 1 到 2 周的推进任务。

核心目标是：

```text
让我知道当前 Pxx 阶段的下一轮 1 到 2 周具体学什么、做什么、是否推进阶段内嵌支线、留下什么输出。
```

---

## 核心定位

本模板服务于以下长期路线定位：

```text
当前主线：应用统计背景下的 Python 数据分析、数据科学、机器学习、AI 工程与 AI 全栈转码能力建设
长期参考：FDU 应用统计人工智能方向
专业底色：统计思维、数据理解、指标设计、模型评估、实验设计、大数据与 AI 应用
执行原则：核心能力深挖，工程能力闭环，大模型方向后期聚焦
输出证据：可运行代码、可复现项目、可解释报告、可展示作品、学习记录
```

请注意：

- 这不是纯计算机科班补课路线；
- 这不是传统统计建模路线；
- 这不是考研复习路线；
- 统计背景不是课程保护线，而是数据理解、指标设计、模型评估、实验设计、大数据分析、RAG / LLM eval 和科研复现中的转码优势；
- FDU 应用统计人工智能方向是长期参考，不是本轮任务的硬约束；
- 本轮任务只服务当前 Pxx 阶段，不提前扩展到后续阶段；一个阶段可以包含多轮任务，也可以跨多个对话推进。

## 最高原则

生成任务安排时必须遵守：

- 只服务当前 Pxx 阶段；
- 不提前进入后续阶段；
- 不重新展开长期路线；
- 不重新生成整个 Pxx 单阶段提示词；
- 不一次安排过多内容；
- 每轮最多安排 1 到 3 个具体任务；
- 必须明确本轮是否推进当前阶段内嵌支线，以及暂缓内容；
- 必须留下可检查的输出证据；
- 必须说明本轮完成后如何继续；
- 如果已达到本阶段完成标准，应提醒我生成下一阶段 Pxx 单阶段提示词；
- 阶段学习结束或阶段复盘时，必须提醒我同步更新《学习路线个人复盘说明手册》。

## 长度与详细度规则

默认生成 **标准任务版**，长度控制在 1200 到 2200 字。

如果我明确说“简单安排一下”，可以压缩到 800 到 1200 字。

如果本轮涉及项目推进、代码实现、数据分析、大数据处理、README、阶段收尾或问题补缺，可以扩展到 2200 到 3500 字。

## 输入信息

我会尽量提供以下内容：

1. 长期路线提示词；
2. 当前 Pxx 单阶段提示词；
3. 最新学习文件夹记录；
4. 本轮完成情况；
5. 本轮遇到的问题；
6. 接下来可投入时间。

如果信息不足，但不影响判断，请基于合理假设继续生成。  
如果信息严重不足，最多追问 1 到 3 个具体问题。

## 阶段内嵌支线推进规则

长期路线中可以存在多个支线方向，包括但不限于：

```text
前端支线
后端支线
大数据支线
数据库 / 数据仓库支线
Linux / 部署支线
Docker / 工程化支线
C++ / 数据结构算法支线
AI 辅助编程支线
论文阅读 / 科研复现支线
大模型应用支线
RAG / LLM eval 支线
```

本模板不使用轮次层面的支线数量限制，也不从外置随机池中临时抽取支线。

正确规则是：

```text
阶段层面决定支线归属：
某条支线是否属于当前 Pxx 阶段，应由长期路线和 Pxx 单阶段提示词决定。

轮次层面决定本轮是否推进支线：
本模板只判断当前 1 到 2 周是否需要推进该阶段内嵌支线的一小部分。
```

本轮是否推进阶段内嵌支线，必须看它是否满足以下条件：

```text
1. 直接服务当前阶段项目或阶段输出物；
2. 解决当前阶段必要问题；
3. 是下一阶段的最小前置准备；
4. 不会抢走当前阶段主线；
5. 能留下明确的代码、记录、报告、README、截图或其他输出证据。
```

如果支线属于当前阶段，但本轮还不适合推进，应写入“暂缓支线”和“暂缓原因”。如果支线不属于当前阶段，应保持冻结观察，不要因为兴趣临时加入。

### 发现阶段提示词漏支线时的处理规则

如果在生成本轮任务时发现当前 Pxx 单阶段提示词可能漏掉了必要支线，不要直接把新支线塞进本轮任务。

正确处理方式是：

```text
1. 先说明：疑似当前 Pxx 单阶段提示词漏掉了某条必要支线；
2. 判断这条支线是否确实服务当前阶段输出物；
3. 建议生成“当前 Pxx 单阶段提示词补丁”，或回到单阶段提示词生成器模板 v2.3.1 小修当前 Pxx 单阶段提示词；
4. 在补丁确认前，本轮只安排不改变阶段范围的必要补缺任务；
5. 不允许因为兴趣或临时想法，把不属于当前阶段的支线加入本轮任务。
```

允许加入本轮的只有一种情况：

```text
该内容不是新支线，而是当前主任务运行所必需的最小工具或最小排错步骤。
```

## 统计背景转码规则

如果本轮涉及统计相关内容，必须落到计算机学习和项目输出中，不能写成传统课程复习。

优先体现为：

- 数据理解；
- 字段含义和指标口径；
- 样本偏差和数据质量；
- 分组统计和 SQL 分析；
- 特征、标签与模型评估；
- 实验对比和错误分析；
- RAG / LLM eval 的样本设计、指标设计和失败案例分析。

如果本轮是纯工具阶段，如 Git、前端基础、Linux 基础，可以不强行展开统计背景。

## 判断规则

生成任务前，必须先判断：

- 我是否仍处于当前 Pxx 阶段；
- 我是否已经完成本阶段标准；
- 当前最需要的是继续推进、补缺、复习、项目实现，还是阶段收尾；
- 本轮任务是否能在 1 到 2 周内完成；
- 本轮是否需要推进当前阶段内嵌支线；
- 当前 Pxx 单阶段提示词是否漏掉了必要的阶段内嵌支线；
- 本轮是否涉及统计背景转化为数据科学 / 大数据 / AI 工程优势；
- 本轮是否涉及 FDU 招生、复试、导师、院系方向等需要官方核查的信息。

如果我还没完成当前 Pxx 阶段，不要建议跳到下一阶段。

## 本轮任务类型判断

生成任务前，必须判断本轮最适合哪一种类型：

- **补缺型**：前置知识不稳，先补基础和练习；
- **推进型**：基础够用，继续学本阶段新内容；
- **项目型**：知识已经够用，应推进最小项目或标准项目；
- **收尾型**：接近阶段完成，应整理 README、学习记录、项目总结和完成标准检查。

不要默认每一轮都学新知识。  
如果旧内容没掌握，应优先补缺，而不是继续加新内容。

---

## 任务粒度规则

每个具体任务必须小到可以开始执行，不能只写抽象建议。

不合格写法：

- 学习 pandas；
- 做一个项目；
- 复习 Python 基础；
- 了解大数据；
- 看一下前端。

合格写法：

- 阅读 pandas DataFrame 选择、筛选、分组的基础用法；
- 用 20 行以内代码读取一个 CSV，并完成 3 个筛选和 2 个分组统计；
- 把运行结果保存为 `outputs/summary.csv`；
- 在学习记录中写下 3 个常用方法和 1 个仍不清楚的问题。

- 代码文件；
- 练习结果；

- README 草稿；

- 学习记录；

- 部署记录。

如果没有输出证据，不能视为真正完成。

## 防浅学习检查

每轮任务完成后，至少要能回答：

```text
1. 我能不能不用教程复现本轮最小成果？
2. 我能不能解释输入、处理过程和输出？
3. 我有没有留下代码、README、截图、记录或报告？
4. 我能不能说清本轮仍然不懂什么？
5. 本轮任务是否服务当前阶段主目标，而不是因为兴趣乱跳？
6. 如果本轮推进了支线，它是否真的服务当前输出物？
```

如果多数答不上来，不建议继续加新内容。

## 禁止事项

生成阶段内任务安排时，不要：

- 重新生成长期路线；
- 重新生成整个 Pxx 单阶段提示词；
- 提前安排后续阶段内容；
- 一次塞入太多知识点；
- 推荐大量资源；
- 把任务写成空泛鼓励；
- 默认我已经掌握未完成内容；
- 把 1 到 2 周任务写成整个阶段计划；
- 把统计背景写成课程复习；
- 把 FDU 长期参考写成每轮硬约束；
- 把阶段内嵌支线误写成随机候选项，或临时加入不属于当前阶段的支线。
