# 资料忠实度与补充 / 纠正规则

## 原则

把用户提供的课程资料视为“这门课怎么走”的主要依据，而不是把它当成一个主题词后重新设计课程。

优先保留：
- 原课程顺序；
- 原课程术语；
- 原作者的项目路线；
- 原课程例子和教学意图；
- 用户明确认可的实践主线。

先对资料做**证据分层**：① 具体课程目录/课次与阶段卡片；② 概括的实践目标链；③ 旧导师提示词中的问题类型、答题优先级与格式规则；④ 未来可能出现的技术和示例。只有①能直接决定完整次序，②只能决定宏观主线，③决定教学协议，④不能充当课程目录。给每个重要路线声明标注原文件与章节/标题；对未提供的具体内容明确写“待收到教材/字幕/阶段记录后确定”。

“忠于路线”也包括保留**这份路线自己使用的代码与名称**。若用户提供的学习路线本来是 P00–P31，就在该路线的 Profile 中保留 Pxx 映射与主线/条件支线状态；禁止把 Pxx 当作所有未来课程的通用编号。不能因为别处有一条“不要硬编码 P00–P31”的规则而抹掉当前资料的原生结构。

## 三类内容必须区分

### 【课程原本内容】
资料明确支持的课程事实、路线、要求、例子和项目。

### 【补充解释】
为了理解而加入，但资料本身没有完整展开的内容，例如：
- 必要前置；
- 关键原理；
- 机制；
- 条件；
- 真实工程差异；
- 验证方法；
- 与已有知识的真实连接。

补充不能反客为主。

### 【纠正 / 更新】
资料存在错误、版本过时、不严谨或会误导学习时使用。

说明：
- 原资料说了什么；
- 问题在哪里；
- 当前应如何理解；
- 是否改变原课程路线。

如果无法可靠核验，不要把怀疑写成确定纠正。

## 多资料冲突

如果同一课程存在教材、syllabus、老师讲稿、字幕、README、旧提示词等多种来源：
1. 先识别每份资料的角色；
2. 用户明确指定权威来源时遵从；
3. 未指定时，课程官方 syllabus / 主教材 / 当前 README 通常决定课程事实，旧提示词更适合提供学习方法；
4. 无法判断时在 Profile 中保留冲突，不擅自合并成一个不存在的版本。

压缩包里有“过时”目录时，先以当前版总路线及与其配套的生成器/手册为执行资料，旧版只作对照。描述用户当前设备、学年、求学目标等历史文本时，写成“资料记载的状态；使用前核实”，不能替用户认定现况。

## 不得静默填空

资料没有给出：考试权重、课程时长、教师要求、版本号、项目 deadline 等具体事实时，不得凭一般经验补成课程事实。

可以写“建议”或“未由资料确定”。

【纠正 / 更新】需要定位原话及可核验依据，再写修改和影响；未核验的技术版本、学校要求和框架选择只能放在“待核验”，不要把怀疑包装成错误。没有已确认更正时写明“暂无可确认的纠正/更新”，仍给出将来遇到过时资料的查证触发条件。不要将生成器自己补的教学建议改写为原作者要求。

## 用户背景的作用

用户背景用于调整：
- 解释深度；
- 前置补齐；
- Evidence；
- 工具协作；
- 跨领域连接。

用户背景不用于篡改课程主轴。例如学习者长期涉及数学、统计、计算机、量化、ML/AI、科研，不代表每门课程都必须同时覆盖六个方向。
