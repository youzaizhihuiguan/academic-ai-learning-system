# Evidence、Stage、Round 与 Learning Debt

## Evidence 原则

Evidence 可在题目、知识单元、项目、Stage 或整条路线层级产生；它不依赖 Stage。每个核心目标写出“学生要交出什么、怎样检验、未达标时返回哪里”，不要把字数、固定题量或打卡次数当成能力证明。

不要把这些当作完成：
- 视频看完；
- 证明看懂；
- 代码跑通一次；
- 模型成功拟合；
- 论文看完摘要；
- AI 给出了答案。

把能力目标转换成可验证输出。

### 数学
- 独立证明；
- 变式题；
- 反例；
- 解释关键条件为什么需要；
- 说出第一步和关键转化。

### 统计
- 推导；
- 模拟；
- 诊断；
- 结果解释；
- 说明假设失效时会怎样。

### 计算机 / 工程
- 可运行代码或项目；
- 测试；
- Debug；
- README / 架构说明；
- 能解释系统行为、数据流和失败层级。

### 量化
- 回测；
- bias 检查；
- transaction cost；
- 时间一致性；
- out-of-sample 验证。

### ML / AI
- baseline；
- evaluation；
- 可复现实验；
- error analysis / ablation；
- 失败案例与限制。

### 科研
- paper note；
- reproduction；
- limitations；
- research questions；
- 实验记录与正式写作。

## Stage 何时启用

须同时有持续推进的需求和**可追溯的课程顺序/项目里程碑证据**，才考虑阶段化。以下信号帮助判断：
- 课程跨度长，预计跨多轮对话/多周学习；
- 前置依赖明显，跳过会造成后续失效；
- 存在多个项目/实验里程碑；
- 需要阶段闸门避免浅学或兴趣支线抢主线。

“长期辅导”的旧提示词本身不是课程地图；目标链不是课时表；技术名词列表不是既定路线。缺具体顺序时可以先使用题目或当前片段的 Evidence，写明日后启用阶段机制的输入条件。

短课程、单章、单个项目或短期专题不应强制阶段化。

## Stage 的职责

Stage 说明：
- 为什么现在学；
- 学什么、不学什么；
- 前置条件；
- 主要输出物；
- 阶段 Evidence；
- 暂缓内容；
- 进入下一阶段的闸门。

若当前 Profile 正在描述一个明确使用 P00–P31 的源路线，保留其原生 Pxx 代码与所属大阶段；若是另一门课程，绝不移植这个编号。编号随当前资料，不由生成器统一重设。

## Round 的职责

Round 是当前 Stage 内的一轮实际推进，不等于整个 Stage。

Round 应回答：
- 本轮最重要的 1-3 个目标；
- 当前任务类型：补缺 / 推进 / 实验 / 项目 / 收尾；
- 本轮最小任务；
- 本轮是否推进某个阶段内支线；
- 本轮 Evidence；
- 完成后继续、补缺还是阶段收尾。

一轮任务不能因为兴趣临时改变 Stage 范围。

## 支线规则

只保留真正服务当前阶段的支线：
1. 直接服务阶段输出物；
2. 解决当前阶段必要问题；
3. 是下一阶段的最小前置；
4. 不抢当前主线。

如果发现 Stage 设计漏了必要支线，优先修正 Stage，而不是偷偷把支线塞进当前 Round。

## Learning Debt

Learning Debt = 为了维持当前主线暂时不彻底解决，但以后必须回来补的知识、技能或验证缺口。

每条 Debt 至少记录：
- debt：具体缺口；
- why_deferred：为什么现在不展开；
- impact：不补会影响什么；
- revisit_trigger：什么时候必须回来；
- blocking：是否阻塞下一阶段。

不是所有不懂的内容都要立即中断主线；也不是所有暂缓内容都值得记 Debt。只有未来确实需要回收的才记录。

区分三种情况：当前问题的必需前置 → 立即补；后续已知里程碑必须掌握且现在展开会抢主线 → 记录 Debt；与当前路线无关或仅为选修的主题 → 暂不学，不记 Debt。短资料也可有个别 Debt，但不因此强行建立完整 Stage/Round 管理系统。

## Review

阶段复盘至少检查：
- Evidence 是否真的完成；
- 是否能解释而不是只复现；
- 是否有未回收的 blocking Debt；
- 是否有支线抢主线；
- 下一阶段前置是否满足；
- 是否需要更新 Course Learning Profile。
