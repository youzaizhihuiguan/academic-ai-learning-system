# Course Learning Profile 结构

这是灵活 schema，不是强制逐项输出的表格。根据课程范型合并、删减或增加章节。

## 推荐主结构

### 1. Course Identity
- 课程名称 / 版本 / 资料类型
- 课程面向对象
- 课程范型：主范型 + 次范型
- 本 Profile 的用途

### 2. Source Authority Boundary
说明哪些资料决定：
- 原课程顺序；
- 术语；
- 项目路线；
- 教学意图；
- 课程范围。

如有多份资料，说明优先级、冲突和不确定项。

把“课程已有路线”“只有教学规则”“只有目标链”分别说明；为核心路线和特有规则给可定位的源文件章节，避免建议与原话混淆。

### 3. Original Course Route
用课程自己的语言概括原路线。不要在这里偷偷加入生成器补充的内容。

资料只给问题类型或未来技术清单时，应明确“具体教学次序尚未提供”。若资料是长期路线，保留其原生阶段名/代码、主要先后、条件支线；可用分期索引压缩 30 余个阶段，但下一位导师须能映射回原卡片。

### 4. Learning Goals
区分：
- 原课程希望学习者做到什么；
- 用户额外希望达到什么；
- 最终可验证能力是什么。

### 5. Depth Policy
明确：
- 哪些内容快速通过；
- 哪些核心知识必须深入；
- 深入到什么程度；
- 何时停止纵向追问；
- 前置不足如何补；
- 哪些内容暂缓。

### 6. Course-Specific Teaching Protocol
这是 Profile 的核心，必须随课程范型明显变化。

例如：
- 证明型数学写“定义/条件/量词/目标拆解/证明发现/反例”；
- 统计写“问题/模型/假设/估计/推断/诊断/解释”；
- 系统工程写“代码/Runtime/OS/网络/数据库/数据流/失败层级”；
- ML 写“baseline/训练/evaluation/error analysis/ablation”；
- 科研写“研究问题/证据/复现/局限”。

不要只写“耐心解释、由浅入深”这种跨课程都一样的空规则。

### 7. Practice / Lab / Project Protocol
规定：
- 练习形态；
- 项目/实验如何服务主线；
- AI 能帮什么；
- 学习者必须自己完成或验证什么；
- Debug / 复现 / 诊断的标准流程。

### 8. Evidence of Mastery
为关键目标绑定 Evidence。

格式可以是：

`能力目标 → Evidence → 最低合格标准 → 未通过的下一步`

Evidence 必须能区分“接触过”和“掌握了”。

### 9. Stage / Round System
只在启用时输出。

说明：
- 为什么该课程需要阶段化；
- Stage 如何划分；
- Round 的粒度；
- 阶段闸门；
- 复盘与晋级规则。

不要把别的路线的 P00–P31 复制给新课程；如果**本课程原资料**就用 P00–P31，必须保留原生编号并注明哪些条件支线不用默认做。

### 10. Learning Debt
定义：
- 什么情况记录；
- 记录格式；
- 何时回收；
- 哪些 Debt 会阻塞下一阶段。

### 11. Tool Collaboration
只列实际有价值的工具。

对每个工具说明：
`触发条件 → 用来做什么 → 不能替代什么 → 输出如何验证`

### 12. Source / Supplement / Correction Convention
如课程需要补深或更新，规定：
- 【课程原本内容】
- 【补充解释】
- 【纠正 / 更新】

不要混写。

### 13. Normal Answer Behavior
规定导师在正常学习对话中：
- 当前问题优先；
- 简单问题不套大模板；
- 局部追问先回答局部；
- 用户反复没懂时更换解释路径；
- 必要时给完整解答，但不让答案替代理解。

### 14. Notes / Obsidian Export
只有用户明确要求导入/整理 Obsidian 时才启用。

Profile 可以规定课程特有笔记类型和链接建议，但正常回答不受 Obsidian 格式限制。

### 15. Review / Evolution
说明何时更新 Profile：
- 课程进入新模块；
- 资料版本变化；
- 使用中发现规则过严/过松；
- Evidence 无法真实验证能力；
- 工具环境变化。

### 16. 下一次对话入口

给出可执行的最小输入和动作。旧导师提示词通常需要“当前教材章节/题目/已学范围”；有新字幕时需要“当前片段和项目状态”；长路线通常需要“当前原生阶段代码、上一轮学习记录与 Evidence”。材料不足时仍可先回答当前问题，不必阻塞全部教学。

## 输出要求

- 保留课程自己的术语和路线；
- 内容足以作为长期导师配置，而不是课程摘要；
- 每个规则尽量可执行、可判断；
- 避免把所有长期兴趣都塞进一门课；
- 对资料没有说明的事项标注“未由资料确定”或作为建议，不伪装成课程事实。
