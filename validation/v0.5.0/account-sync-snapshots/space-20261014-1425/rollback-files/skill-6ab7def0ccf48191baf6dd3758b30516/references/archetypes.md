# 课程范型与差异化学习协议

选择一个主范型；必要时加入次范型。范型决定“怎样学”，不是给课程贴标签。

## 1. 证明型数学

适用：数学分析、高等代数/线性代数、实分析、概率论理论部分等。

核心协议：
- 先识别定义、条件、量词、目标与题型；
- 强调“第一步为什么想到”“每一步为什么合法”；
- 证明先拆目标，再选定义/定理/构造；
- 区分直觉与严格证明；
- 用反例说明条件为什么不能删；
- 能用基础方法就不以高阶观点替代；
- Evidence：独立证明、变式题、反例、条件解释、从答案迁移到同类题。

数学分析额外重视：局部/整体、极限与交换顺序、量词顺序。
高等代数额外重视：结构、转化、秩/维数/线性相关/线性变换之间的联系。

## 2. 计算型数学 / 数值

适用：数值分析、科学计算、计算型优化等。

核心协议：
- 问题与误差目标 → 方法 → 条件 → 推导 → 稳定性/收敛性 → 复杂度 → 数值实验；
- 区分理论误差、浮点误差和实现误差；
- Evidence：推导、误差分析、数值实验、对比方法、失败案例。

## 3. 概率 / 随机过程

核心协议：
- 随机对象 → 样本空间/分布 → 条件 → 期望/方差/依赖结构 → 定理 → 模型解释；
- 理论部分沿证明型数学规则；应用部分加入模拟与解释；
- Evidence：推导、构造反例、模拟、解释条件与极限结论。

## 4. 统计建模

适用：数理统计、回归、多元统计、时间序列、贝叶斯、因果推断等。

核心协议：

`问题 → 模型 → 假设 → 参数 → 估计 → 推断 → 诊断 → 解释 → 局限 → 模拟/数据验证`

必须避免只会调用函数。Evidence 优先使用推导、模拟、诊断、结果解释、模型比较和失败条件。

## 5. 金融 / 量化

在统计建模协议上额外检查：
- 时间顺序；
- look-ahead bias；
- survivorship bias；
- data snooping；
- transaction costs；
- train/validation/test 的时间一致性；
- out-of-sample performance；
- 风险暴露与稳定性。

Evidence：回测 + 偏差检查 + 成本 + 样本外验证 + 结果解释，不把单次高收益当学习证据。

## 6. 编程语言

适用：Python、C/C++、JavaScript 等语言课程。

核心协议：
- 语法服务于程序模型，不把课程退化为 API 清单；
- 建立值/类型/变量/控制流/函数/模块/内存或运行时模型；
- 关键代码要求能读、能改、能 Debug、能测试；
- AI 可以生成代码，但学习者必须验证；
- Evidence：独立小程序、修改已有代码、Debug、测试、解释运行行为。

## 7. 数据结构与算法

核心协议：

`输入/输出/约束 → 朴素方法 → 瓶颈 → 优化 → 正确性 → 时间复杂度 → 空间复杂度 → 边界情况 → 实现`

Evidence：独立推导思路、正确性解释、复杂度分析、变式题、实现与测试。

## 8. 计算机系统 / 工程 / Web

适用：操作系统、网络、数据库、后端、Web、AI 全栈、部署等。

核心协议：
- 原课程实践路线可作为主线，但关键技术必须解释“为什么存在、为什么这样设计、下面发生了什么”；
- 建立 `代码 → Runtime → OS/Browser → Network → Database/Storage → 系统行为` 的可运行心智模型；
- 解释数据流、边界、框架隐藏的复杂度、真实工程差异、失败模式和排查层级；
- 允许沿当前问题的纵向因果链深入，但不横向罗列技术栈；
- 教程 Demo 与真实工程要区分；
- Debug 使用 `复现 → 缩小范围 → 根因 → 最小修复 → 测试 → 回归检查`。

Evidence：可运行项目、测试、Debug 记录、架构/数据流解释、替换框架后仍能说明底层原理。

## 9. ML / AI

核心协议：
- 问题定义 → baseline → 数据与预处理 → 模型 → loss/objective → 训练 → evaluation → error analysis/ablation → 局限；
- 数学/优化只补当前模型真正依赖的部分；
- 代码必须能解释数据流、张量形状、训练循环和评估；
- Evidence：baseline、可复现实验、指标、错误分析/ablation、失败案例、模型/数据限制。

## 10. 科研 / 论文

核心协议：

`研究问题 → 文献 → 方法 → 假设 → 数据/实验 → 结果 → 证据 → 局限 → 复现 → 写作 → 下一研究问题`

Paper Note 不能只做摘要；必须识别 research question、motivation、data、method、assumptions/identification、results、limitations、my questions、可复现点。

Evidence：paper note、复现、limitations、research questions、实验记录、正式写作。

## 11. 混合型课程

只在课程确实跨范型时组合。

示例：
- AI 全栈：工程/Web 为主，编程语言为辅；
- 机器学习理论课：ML/AI 为主，证明型数学/优化为辅；
- 金融计量：统计建模为主，金融/量化约束为辅；
- 概率计算课程：概率为主，计算型数学/编程为辅。

组合时不要把所有范型的模板全部拼接；只继承当前课程真正需要的规则。
