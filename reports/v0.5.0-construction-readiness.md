- 状态：**READY FOR ISOLATED IMPLEMENTATION / NO IMPLEMENTATION PERFORMED**
- 日期：2026-10-10（Asia/Tokyo）
- 设计权威：[`v0.5.0-fusion-architecture.md`](v0.5.0-fusion-architecture.md)。
- 初始施工前置：保留原五 Skill 安装版和 GitHub 快照，先复用仓库原有集成测试与 `progress/computer.md` 的 source-of-truth 约束。
- 版本规则：`v0.5.0` 是**目标版本号**；只有实际开发、回归、验证、用户验收后才创建发布标签。设计文档本身不能把安装状态升级成 v0.5.0。
- 本文件明确排序与施工闸门，但不会创建新 Skill、调用用户 Vault、写个人 Progress 或修改旧 Skill。

## 0. 范围及停止条件

**In scope：**
- 创建独立 `interactive-learning-designer`（#6）和 `learning-progress-coordinator`（#7）两个 Skill；独立 description、`SKILL.md`、必要 reference、UI metadata 与完整可复用测试。
- 先证明独立触发与单 Skill 降级，再对 Course Tutor Builder / 三个 Tutor 做**最小兼容补丁**；Obsidian 如无实际问题保持不动。
- 为阶段恢复、真实 Evidence、复习队列与交互观察设计安全、可验证的交接。
- 基于测试确认是否安装。未过闸门不发布 `v0.5.0`。

**Out of scope：** Grilling 融合、第四个学科导师、独立网页教学平台、强制游戏化/强制问卷、重新设计 P00–P31 路线、批量迁移旧笔记、自动将真实成绩写入 public 仓库、启动持续后台进度记录。

**立即停止并修复的 blocker：** 错误的专业结论；自动触发导致普通问答失效；隐私数据写到公开存储；未验证就宣称掌握/已保存/已运行；Stage 或 CLP 被擅自重排；技能间隐式通信被设计成运行时依赖；现有五 Skill 基线任务回归失败。

## 1. 分阶段施工：顺序与可交付物

### G0 — 冻结与基线读取

1. 记录 `main` 当前 HEAD、目标工作分支、已安装五 Skill 的版本/描述/文件完整性；只读原 `README.md`、两份 2026-09-27 报告、`references/evidence-staging.md`、`references/profile-schema.md`、CLP、Progress。
2. 建立独立实现分支，从已核验设计+施工计划提交点创建；**不要在 main 直接试写 Skills**。
3. 把历史 12 个系统情境检查转成可重复测试集；保存旧 Skill 路由/输出作为回归基线，不把模拟题目写为用户实际 Evidence。
4. 确认技能运行环境与 ChatGPT Intelligent UI 的实际可用范围。不预设复杂组件能跨聊天持久存在。

**Exit gate：** 五个旧 Skill 内容未修改；实现分支、源 ref、测试基线可重读。未完成不能进入 G1。

### G1 — 第六个 Skill：交互学习设计器

交付目标：`skills/interactive-learning-designer/`（隔离工作分支），独立可触发且不抢普通学科导师职责。

- `SKILL.md` 保持简洁：定位复杂原生学习交互（跨步骤状态、输入、即时反馈、交互探索）；根据教学目的选表达形式；说明单 Skill/无 UI 时降级；不要枚举强制模板。
- 最小一层 references：`interaction-contract.md`（Learning Intent、UI Observation、Evidence boundary）；`interaction-qa.md`（参数边界、数学正确性、重置、状态一致、界面操作是否真实传回）。
- 学科内容权威属于领域 Tutor/真实输入；交互设计器不可自称统计结论经过推断或代码已经运行。
- 兼容复杂交互与普通原生小组件：普通 Tutor 无需调用它也能直接使用平台已有 UI。
- 交互状态仅能在确实可观察和传回的范围内声明；没有回传的本地控件操作不得成为持久 Evidence。

**Exit gate：** 复杂交互独立测试通过，普通问答和“直接给完整证明”不被截胡；错误参数、边界、重置、不可用回退通过；明确表明模拟/示意/真实计算的来源。

### G2 — 第七个 Skill：学习进度与复习协调器

交付目标：`skills/learning-progress-coordinator/`，带清晰触发描述和证据规则。

- `SKILL.md`：仅在恢复/保存真实学习进度、Evidence、复习计划、阶段证据审查、跨对话继续等任务主导；不讲授课程，不重新生成 CLP。
- references：`progress-contract.md`（Progress、Debt、Review Queue、Evidence 粒度及出处）；`review-policy.md`（retrieval、spacing、interleaving、辅助程度与调整）。
- 先读现存 Profile/Progress，依学科 Evidence 判断写入范围；不把“看过 AI 解答/点过 UI/提交一道选择题”当无提示掌握。
- 复习建议优先真实错误、重要前置、过去成绩和考试时点；不同知识点可异步安排。不要承诺不存在的 FSRS 状态、自动通知或精确记忆概率。
- 区分“已构建复习计划”与“已经创建未来任务”。需要外部存储写入才算保存；写入后回读校验，异常时不吞错。
- 本仓库 `public`：先只以**虚构数据的测试夹具**验证读写。真实个人 Evidence 持久化必须单独确认私有目标位置与授权；目标未知时给出待保存草案，不向 public repo 写明细。

**Exit gate：** 幂等保存/重复操作安全、旧版 Progress 读取、冲突防护、证据界限、隐私禁写、无权限回退全部通过。

### G3 — 最小兼容集成（只在 G1/G2 通过后）

- `course-tutor-builder`：CLP 可声明适当的交互与复习策略，保留原先 Evidence/Stage/Debt 的唯一来源权威；**不重复存储运行时进度**。
- `rigorous-math-tutor`：少量条件式知识断点诊断、交互作为表达手段、无提示验证，原严格证明不变。
- `statistics-quant-lab`：交互抽样/模拟不冒充数据或理论结论；原统计结论标准和 post-hoc-power 约束不变。
- `computer-ai-tutor`：AI 辅助编程后可以**按需**进行预测—观察—解释、变式练习；不干扰交付流程。
- `obsidian-academic-kb`：如无具体可证实集成 blocker 保持字节级不变；仍只在用户明确请求知识库操作时触发。

兼容规则优先**极简插入/引用接口**，避免把第六、第七个 Skill 的整套机制粘到三个 Tutor 的主体中。不同 Skill 不保证自动同时加载，缺席时每个 Tutor 仍须能独立正常工作。

**Exit gate：** 新机制在需要时出现，但无额外框架和冗长模板；原五 Skill 路由回归通过。

### G4 — 系统级验证与真实学习试点

按设计基线 M01–M20 执行，再补充关键反例：
- 数分极限、代数矩阵秩、微分方程方向场：可视操作正确且能回到严格证明；不强制 UI。
- 统计抽样分布、回归模型诊断：推断与模拟边界明确。
- Python 多次调用默认参数、递归调用栈、AI 生成代码：能解释行为和在有执行环境时复现；预测失败后更新理解，不伪称已运行。
- 一次普通数学问答；一次明确完整解答；一次用户不愿考试/复习；一次 UI 当前组件不支持的情况。
- 先给提示、后独立完成同一任务；延迟后独立变式；无观察结果的 UI 练习：Evidence 等级不得混淆。
- 仅用假数据在隔离私有/本地夹具模拟跨会话恢复；未授权场景确保不写 public repo。
- 课程资料题目溯源与错题专项：真实出处、AI 补充与未知答案区分。
- 验证显式 Obsidian 请求能走原路径；普通教学不会擅自沉淀。
- 在至少两个不同对话任务的 Skill 路由与交接下观察行为；不能把规则上的“应触发”当平台实测的触发率。

**Exit gate：** 20 项核心 + 历史 12 类路由边界均通过；故障/降级行为有真实记录。若发现平台能力限制，记录限制并收敛范围，不假装可用。

### G5 — 安装、版本与收尾（仅验收后）

1. 完整备份和比较原五 Skill 的版本；逐个安装/更新，核对描述与文件，对新 Skill 做实际触发复演。
2. 将经过验证的安装 Skill 快照同步到 `skills/`；README、报告与真实版本号一致。
3. 保持 source/CLP/Progress/Vault 分层一致；撤销任何测试临时数据及不需要的权限。
4. 在全部安装验收通过时才更新 status 为 `RELEASED` 并创建 Git tag `v0.5.0`。没达到标准可使用 `v0.5.0-rc.1` 等预发布标识，但不能把设计 checkpoint 标为正式 release。
5. 以安装前五 Skill 快照作为回滚基线；恢复时只恢复 Skill 内容与描述，不倒写真实学习进度。

## 3. 原始设计追踪：实施遗漏检查

每个交付 PR / checkpoint 必须确认：

1. teach：长期学习目标与高质量资料、ZPD、主动回忆、间隔与交错均有明确执行者。
2. learn：知识依赖/断点/误解诊断按需启用；不机械 Probe-DAG-Quiz。
3. Education Agent Skills：有提示 vs 无提示证据；检索类型、间隔、交错与复测调整都落地。
4. Learning Opportunities：AI 写出的代码不自动等于学习者已掌握，项目后反思为可选。
5. Universal Exam Prep：真实材料定位、课程资料/AI 补充区分、错题和考前分支。
6. Grilling：仅项目审查，不进入日常学科学习。
7. Intelligent UI：跨学科原生能力，不强制游戏化；复杂交互专属职责；状态与长期证据隔离。
8. 原五 Skill：路由、严谨性、CLP 原生路线、Obsidian 显式触发、WebCodex 证据边界不退化。

## 4. 施工恢复入口与发布闸门

下一次继续先读取本文件、融合设计基线、`README.md`、HEAD 与五个 Skill 当前文本，核对 `main` 和施工分支是否一致。**从 G0 开始**，不要因为计划完整就跳过校验；每个 G 阶段先报告真实证据，再进入下一阶段。不得继承本次模拟数据为用户掌握事实。发生中断以已提交的分支/报告恢复，不依赖对话上下文。

状态口径：
- `DESIGN BASELINED`：设计文档保存并回读；Skill 未变。
- `READY FOR IMPLEMENTATION`：仅施工准备完成。
- `IN VALIDATION`：测试真实执行中。
- `RELEASED v0.5.0`：安装与全回归验证完成，并打 tag 后才能使用。
