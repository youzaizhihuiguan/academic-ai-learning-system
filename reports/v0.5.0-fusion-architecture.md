## 1. 设计问题与不可破坏的基线

现行管线是 `Source / Curriculum → Course Learning Profile (CLP) → Domain Tutors → 按需真实执行/验证 → Progress/Evidence → 用户显式要求时 Obsidian`。原有五 Skill：

1. `course-tutor-builder`：读取真实课程资料，生成长期 CLP；保持课程自己的术语、顺序、权威层级和证据标准。
2. `rigorous-math-tutor`：定义、量词、条件、证明、计算及独立数学能力。
3. `statistics-quant-lab`：统计推断、实验设计、模型评价与不确定性；禁止把 observed/post-hoc power 当额外证据。
4. `computer-ai-tutor`：代码、运行时、系统机制、算法、AI/ML 工程与可复现验证。
5. `obsidian-academic-kb`：**仅在明确请求时**沉淀已验证或明确标记未验证的长期知识，不自动导出。

原有：CLP 稳定、Progress 可变；Evidence 不等于看懂、点击、跑通；Learning Debt 是明确推迟的必要前置，不是复习队列。Stage/Round 只在资料与真实里程碑支持时启用。真实运行需工具和证据；不假装访问本机、工具或 Vault。普通问题直接回答，不强制测验、阶段表或冗长交接。

## 4. 交互能力设计原则（不限制创造性）

- 自由生成最适合当前认知任务的界面：可包含可操作对象、图形、公式、步骤、输入、反馈、比较或混合形式；不得规定“每题一滑块/每章一游戏”等固定模板。
- 能在常规文字里讲清时直接讲清；当前对象变化、连续操作或即时验证能降低认知/交互成本时积极用 UI。
- 客户端按钮/滑块/输入状态仅代表**当前界面内部状态**。除非通过支持的真实交互事件明确送回并经确认，否则不能假设 Tutor/Coordinator 自动获得完整用户操作轨迹。
- 即时计算与静态判题规则必须正确，检查异常输入、重置、边界值和状态一致性；开放性推理、数学证明、统计解释与真实代码执行仍由领域 Tutor/相关工具核对。
- 面对交互不可用、平台/模式不支持、状态丢失或用户需要纯文字时自然降级。不能因 UI 不可用阻塞课程学习。
- 不以界面得分、播放、点击或模型生成动画直接认定独立掌握。没有证据就保留未知。

## 5. 长期学习闭环

**领域 Tutor：** 识别局部卡点；遇到反复不理解或显著前置断点时进行最少量、目标相关的知识诊断，区分粗心、孤立缺口、系统性误解；解释并通过新例子验证。直接要求完整答案时立即提供，不强制测试。根据学科标准判定学习者是否独立完成。

**Progress Coordinator：** 读取已存在的 CLP 与 Progress；从可信 Evidence 中识别需要再测的内容；安排合适的自由回忆、提示回忆、变式、间隔复测与区分相近概念的交错练习。复习计划是建议/队列，不是已设置的未来任务。用户要求定时提醒时，只有真正授权并建立定时任务后才称创建成功。

**概念区别：**
- `Progress`：当前位置、已经完成/验证的任务、下一步。
- `Evidence`：观察到的产出、辅助程度、验证方式、能支持与不能支持的结论。
- `Learning Debt`：主线暂缓、未来必须补的前置缺口。
- `Review Queue`：已接触或已学、将来需要主动检索或复测的知识，不等于 Debt。

考前复习只在真正有考试、试题或考试目标时作为课程子工作流启用；不能以学习科学为由擅自重排原教学路线。

## 6. 跨 Skill 数据交接（概念契约，不保证 Skill-to-Skill RPC）

### A. Learning Intent：Tutor → 复杂交互设计

最低需要：`course/topic`、`goal`、`known_prerequisites`（若已知）、`correctness_constraints`、`learner_task`、`assistance_policy`。缺信息可给安全范围的当前演示，不编造课程进度。

### B. Interactive Observation：UI → Tutor

至少区分：`interaction_type`、`observable_answer_or_result`、`feedback_rule`、`evidence_limit`。只在界面内部发生、没传回对话/真实文件的事件，**不算可审计的长期 Evidence**。

### C. Evidence Assessment：Tutor → Coordinator

最低内容：`course/topic`、`task`、`assistance`（示范/提示/无提示等）、`observed_output`、`verification`、`conclusion_scope`、`source_ref`；可选 `retention_check_due`。一题答对不能自动升级整章或永久“已掌握”。

### D. Progress Update：Coordinator → 实际持久文件

加载当前版本并核对来源/权限，只写真实变化；保留旧证据链接，避免覆盖并发更新；写后回读核验目标位置与内容。无可用写权限时只提供可复制的更新草案，并明确**未保存**。没有证据时写“未知/未核对”，不误写“尚未完成”。

## 7. Source-of-truth、权限与隐私

- 稳定课程路线/协议：`sources/` 与 `profiles/`；可变状态：`progress/`（当前已有 `progress/computer.md`）。原项目仓库保存程序测试/数据原始产物，Progress 只保存证据位置与可支持结论。
- `skills/` 是安装版的恢复快照，不是平行运行目录。真实用户 Vault 不因 Progress 变动自动改写。
- 本仓库现为 **public**。个人学习明细、成绩、私人资料不得默认写入公开仓库。第七个 Skill 首先需要明确**隐私安全的长期记录目标及权限**；可使用用户授权的私有存储，或仅在公开仓库保存不含个人敏感信息的结构/示例。
- 原始 Profile 与 Progress 不可依“猜测的历史”自动合并；需要跨对话恢复时以当次真实可访问的记录为准。
- WebCodex、GitHub、Wolfram 等工具只在实际可用时调用。UI 模拟值、真实执行观察与理论结论分开记录。

## 8. 施工前的不可退化约束

1. 原五 Skill 可独立完成历史基线任务，三导师不因新 Skill 缺席而停止教学。
2. 普通问答不强制插入问卷、游戏、诊断、复习队列、Progress 写入或 Obsidian 导出。
3. 数学命题的条件、量词和严格证明不退化；统计结论保留设计与不确定性限制；工程模型的静态演示不冒充运行证据。
4. 明确要求完整解答时直接完成；必要前置诊断按需触发而非一律先测。
5. CLP 路线和原生阶段代码不重排。P00–P31 仅属于既有计算机路线。
6. 复习计划不得伪装成已预约提醒；UI 状态不得伪装成长期 Evidence；未写入不得声称已保存。
7. 无真实用户授权不得向公开 repo 写入细化的个人学习记录；无真实 Vault 权限不得声称写入 Obsidian。
8. Skill 自动选择不是稳定 RPC；每个复杂流程都应具备单 Skill 独立响应/交接草案的降级路径。

## 9. 最低验收矩阵（将在施工计划中展开）

- M01 普通数学解释不误触发复杂交互设计；M02 明确要求完整证明直接提供证明。
- M03 数学交互参数与几何/符号结论一致；M04 复杂 UI 中断、重置与边界值正确。
- M05 统计模拟区分假设/随机生成/经验数据；M06 代码可视化与真实执行证据不混淆。
- M07 前置诊断区分孤立错误与系统误解；M08 不强制所有学生 Probe/DAG/quiz。
- M09 AI 辅助代码后的可选理解检查不打断项目交付。
- M10 无提示证明与有提示答题的 Evidence 等级不同；M11 UI 内部点击未上报不能持久化为掌握事实。
- M12 检索/间隔/交错复习尊重课程先修与实际表现；M13 Learning Debt 与 Review Queue 不互相污染。
- M14 考前题目的讲义/真题来源、AI 补充和未知答案可追溯。
- M15 跨聊天读取旧 Progress 可以恢复；M16 不可读/不可写时不幻觉恢复或保存。
- M17 五 Skill 原有系统级 12 类路由/边界回归不退化；M18 多 Skill 缺席与触发冲突时也能完成任务。
- M19 未经授权不得公开个人 Evidence；M20 Obsidian 仍然只在明确请求时启用。
