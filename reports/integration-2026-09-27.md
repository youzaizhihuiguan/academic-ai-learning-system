## 3. Profile → Tutor：三个原生阶段的实际答题复演

复演时只使用 Profile 的课程规则、原路线相应阶段卡片和题目中的信息；这些题目是**用于磨合的测试情境**，不宣称是用户当前的学习任务。

### P01：基础编程与 CSV 小工具

**情境：** 同一进程连续处理两份 CSV；第一份分数 80、100，第二份 0、20。为什么第二份的条数和平均值不对？

**计算机 Tutor 的回答：** 先比较两次调用的输入与局部 / 跨调用状态。函数签名中的 `scores=[]` 在定义函数时产生一份列表；第一份加入 80、100 后，下一次不传 `scores` 又沿用它，所以第二份的 0、20 加在旧数据后。预测第二次结果为 4 条、平均 50，而它本应是 2 条、平均 10。将默认参数改成 `None`，在调用内部创建新列表，并连续运行两次回归。这里仍服务 P01 的文件、函数、异常和可解释小项目，不转去 P04 数据分析或重设计路线；一次 bug 修复不等于 P01 阶段闸门全部完成。

**使用感：** Profile 给目标和深度，Tutor 直接处理当前 bug；不把 P00–P31 再复述一遍。真实执行见第 4 节。

### P09：机器学习数据流与统计评价

**情境：** 一个 tabular 分类脚本先用整张表计算预处理参数，然后才划分训练 / 验证，训练 AUC 0.98、验证 AUC 0.61。问状态在哪层被学到、下一步改什么。

**计算机 Tutor 主导的回答：** 先追踪预处理参数何时从哪些行学到，圈出全表拟合这一步，再让预处理仅在训练折 / 训练集拟合，对留出集只应用既有变换。固定切分与标签窗口，重跑同一模型及基线，比较改动前后指标与错误样本。**不能从两个数字直接断定唯一根因**；AUC、泄漏、划分单位和泛化结论由统计导师提供判据。如果用户问“这个 AUC 到底能否支持上线”，统计应成为主导。无数据与可运行项目时这里只是诊断设计，不能声称已改善指标；不因一个评估问题跳到 P22 深度学习。

**使用感：** 代码状态和指标可信度在同一条诊断链，工程和统计没有各讲一半。

### P26：RAG 项目的引用错误

**情境：** 项目日志称检索结果中有正确段落 `S7`，但答案给出 `S3` 的引用。问应从哪里查。

**计算机 Tutor 的回答：** 把 `S7` 从检索、重排、提示词拼接到答案引用映射逐层跟踪，检查每层是否保留原文片段和 `source_id`；最小复现固定一组带 ID 的片段，记录传入模型的上下文和输出引用，定位是检索、映射还是生成阶段失真。提供的日志只是题目给定线索，未在用户环境复核；只有获得实际运行记录才确定根因。若用户进一步问“在整个问题集里引用错误率是否改善”，统计导师制定抽样、指标和不确定性判断。当前目标是 P26 的可追踪 RAG，不提前激活 P27 微调或 P28 Agent。

**使用感：** 能沿当前失败的因果链深入，却不把整个路线倒进回答。

## 5. Tutor → Obsidian：先学会，再显式沉淀

P01 的正常答题和执行没有导出笔记。之后复演明确请求“把这个整理进 Obsidian”。对**当前会话真实用户 Vault 未授权访问**这一情况，应给建议位置 `02 Concepts/Python 默认参数与可变状态.md` 和下列完整可复制内容，明确**尚未写入用户 Vault**。Concept 保存可迁移机制；P01 Course note 只需按需链接这份概念；测试运行本体留在仓库的 validation / 报告，不复写完整聊天。

````markdown
# Python 默认参数与可变状态

Python 在执行 `def` 时计算默认参数。调用时省略该参数，会重复使用同一个默认对象；若函数修改默认列表，后续调用可见旧状态。

```python
def add_score(value, scores=[]):
    scores.append(value)
    return scores

add_score(80)  # [80]
add_score(20)  # [80, 20]
```

需要每次调用新列表时，用 `None` 作默认值，并在函数内创建列表。调用方显式传入列表时是否修改它，仍取决于接口约定。

本次隔离 CSV 测试：第一份 `(2, 90.0)`；第二份原实现错误为 `(4, 50.0)`，修正后为 `(2, 10.0)`。这只验证样例的跨调用状态，不表示用户项目已修复或 P01 已完成。
````

另在**隔离的模拟 Vault**中预置一页同主题 Concept：先列文件并读取现有内容，再补充机制、修法及真实运行证据；完成后仍只有一页，核查保留旧标题和新增证据。这检验了“有权限时先查现有节点再编辑”的行为，**不等于已读写用户 Vault**。没有为了一个 bug 新建 Lab、课程页、空 WikiLinks 或每日笔记。

## 6. 三个跨领域磨合

| 问题 | 主导与一条连贯的回答 | 边界 |
| --- | --- | --- |
| 数学 + 统计：“样本均值为何无偏，是否保证单次估计很接近？” | 统计导师直接利用期望线性性给出 `E[X̄]=μ`，再说明无偏不保证一次接近；独立同分布时 `Var(X̄)=σ²/n`，若相关则需计入协方差。 | 短推导留在统计；要求独立严格定理证明时才由数学主导。 |
| 统计 + ML 工程：“上线 AUC 降低，是泛化失败还是 serving 管线错位？” | 先固定样本、标签窗口和指标口径；复放相同样本比较离线与线上特征 / 模型输出，排除预处理、字段和版本不一致，再按时间 / 人群分层评价分布变化和不确定性。 | 若判断 AUC 结论是否可信，统计主导、工程提供日志与重放；若仅修请求解析故障，工程主导。没有真实日志不能归因。 |
| 数学 + ML：“P09 逻辑回归的梯度更新为什么是 `(p-y)x`？” | 计算机 / ML 教学先设 `z=wx, p=σ(z)`，对交叉熵按链式法则得 `dL/dz=p-y`，故 `dL/dw=(p-y)x`；回到权重如何更新和符号如何影响预测。以 `x=2,y=1,w=0.3` 做数值差分，解析值与差分均约 `-0.708687388`，差距约 `2.45e-11`。 | 数值差分验证这个实现点，不能代替推导；若单独要求严格凸性或定理证明，再由数学主导，不把 P09 问答转成整门优化课。 |

## 7. Skill 修改、复杂度与未解决事项

**Skill 修改：零。** `course-tutor-builder` 已能从真实资料保留 Pxx 并区分原路线、历史材料和教学协议；三个 Tutor 的主导边界、WebCodex 的条件访问以及 Obsidian 的显式触发足以支持上述链路。既然摩擦通过 Profile / Progress / 来源清单解决，就没有“真实问题确实来自 Skill 且只能小改”的证据；因此没有对任何 Skill 解冻，也没有触发修改后的盲测或同步流程。五个安装本体只作完整快照备份，不在快照里编辑。

主动避免的复杂度：没有第六个总管 Skill；没有把全路线复制进 Tutor；没有对其他课程套 Pxx；没有把 Profile 当实时日记；没有为每个 Pxx 新建空 Progress；没有独立 Evidence 库再复制项目结果；没有把 Source 再放进 Vault；没有普通答题自动导出；没有统计与计算机各给一份断开的结论；没有从历史手册制造当前 Learning Debt。仓库内的 `skills/` 是恢复快照，不与网页端安装目录竞争日常配置权威。

仍需在真实使用中解决：用户实际当前 Pxx / 最近 Evidence、现行个人复盘手册（如果有）、设备与目标的现况、真实项目数据 / 日志、Secure Tunnel 和真实 Vault 的访问权，以及平台隐式触发的长期表现。本次三阶段与跨领域测试使用真实路线和实际执行证据，但未测量网页端自动选 Skill 的概率；P09/P26 题目是受控情境，不能冒充用户真实模型或 RAG 项目结果。
